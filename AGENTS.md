# AGENTS.md

Це основна точка входу для агентів у цьому репозиторії.

## Мова

За замовчуванням працюй і відповідай українською мовою, якщо користувач не попросив інше.

## Перед початком роботи

1. Прочитай `AGENTS.md`.
2. Прочитай `PROJECT-INFO.md`, якщо файл є.
3. Прочитай 1-3 найновіші файли з `.agents/journal/`, якщо вони є.
4. Використай цей контекст перед стартом задачі.
5. Не повторюй уже виконану роботу без чіткої причини.
6. Незавершені `next steps` з останніх журналів вважай пріоритетними.

## Під час роботи

- Дотримуйся правил з `CONTRIBUTING.md`, `README.md`, `DEVELOPMENT.md` і `RELEASE_CHECKLIST.md`.
- Використовуй runtime з `.nvmrc`.
- Не чіпай чужі незавершені зміни без потреби.
- Якщо змінюється поведінка, додавай або оновлюй тести.
- Якщо змінюється setup, workflow або архітектурний опис, оновлюй відповідну документацію.

## Наприкінці сесії

1. Створи новий запис у `.agents/journal/`.
2. Назва файлу: `YYYY-MM-DD-HHMM-ide-model-short-title.md`.
3. Запиши дату і час, IDE / агента, модель, chat id якщо є, ціль задачі, що зроблено, змінені файли, команди/перевірки/тести, результат, наступні кроки, ризики/нотатки.

Користуйся шаблоном з `.agents/templates/journal-entry-template.md` і правилами з `.agents/JOURNAL-RULES.md`.

## MCP політика

Always-on MCP:

- `chrome-devtools`
- `context7`
- `desktop-commander`

Маршрутизація:

- Для сайтів, браузера, UI-перевірок, layout, скріншотів і console errors спочатку використовуй `chrome-devtools`.
- Для docs по бібліотеках, SDK, API і framework reference спочатку використовуй `context7`.
- Для локальних файлів і системних дій спочатку використовуй `desktop-commander`.
- Не питай, який MCP використати, якщо намір користувача і так очевидний.
- Якщо потрібний MCP недоступний, продовжуй з найкращою локальною альтернативою і коротко зазначай це.

## MemPalace

MemPalace у цьому проєкті не використовується. Якщо його додадуть пізніше, не індексуй весь репозиторій без розбору. Джерелом правди мають лишатися `PROJECT-INFO.md`, entry-point файли та `.agents/journal/`.

## Спільне канонічне ядро

Робочі практики нижче — спільні для всіх проєктів workspace. Повна версія — у канонічному
`_client-template/AGENTS.md`; тут лише пойнтер, ядро не дублюється. За конфлікту правил перемагає
канонічне спільне ядро.

- **Verify-Before-Done** — жоден файл-результат не готовий без перевірки: розмір > 0, цілісність за типом, зміст vs очікуване.
- **Definition of Done** — не оголошуй задачу завершеною без доказу (тест/збірка/скрін); фінальний рядок звіту: «зроблено X, НЕ зроблено Y, на проді: так/ні».
- **integrations** — опційні модулі читай лише коли ввімкнено в `.agents/config.md` (секція `integrations:`).
- **Секрети** — тільки macOS Keychain (`service = {project}-{service}`, `key = {key}`), ніколи у файлах репо; plaintext = скомпрометований → ротація.
- **Журнал по ходу роботи** — фіксуй суттєве одразу, не лише в кінці сесії (контекст може обірватись).

Машиночитний маніфест скелета — `.agents/STANDARD.md`; факти проєкту (git remote, стек, команди) — `.agents/config.md`.

## Code Indexer

- Основний індекс цього робочого дерева: `nutrition-app`.
- Окремий індекс сусіднього робочого дерева з голосовим введенням: `nutrition-app-scale`.
- На старті роботи після читання локального контексту виконай `briefing(project="nutrition-app")`; для голосового введення також `briefing(project="nutrition-app-scale")`.
- Не змішуй гілки: перевір `git status` і `git worktree list` перед змінами.
- Конфіг індексування: `.indexer.toml`. Особисті записи, секрети, службові runtime-файли й тимчасові макети виключені.
- Журнал і `PROJECT-INFO.md` залишаються джерелом правди; профіль та картки Code Indexer є їхньою пошуковою копією.
- Експорт для Git: `codeindexer export --skip reports --project nutrition-app --dir .codeindexer`. Для профілю сусіднього дерева повтори команду з `--project nutrition-app-scale`.
- Детальні результати перевірок доступу зберігай локально. Публічний репозиторій не повинен отримувати особисті дані або діагностичні дампи.
