## Зроблено

Додав ProfileContext у власний native HOME. Імпортовані sources мають точний manifest, SHA256, canonicalHome та приватні файли; невідомі/змінені/відсутні джерела не відкидаються мовчки. Увесь контекст зберігається без обрізання до400000bytes. Runtime вимагає заздалегідь створене сховище й не створює порожню заміну після втрати memory.json. initialize=True є лише явним операторським provision; у production worker такого bypass немає.

Нові підтверджені факти додаються окремо, зберігаючи вихідні факти. Revision, proposalId і semantic digest дають ідемпотентність після restart. Файли іншого HOME не приймаються. Модель не отримує terminal/file/memory auto-write; commit доступний лише trusted parent через typed IPC після користувацького підтвердження.

Core має context/commitContext, спільна черга серіалізує commit. Скасований GET не вбиває authority з активним model turn; недоступний commit чекає physical retire до наступного профілю. AppGateway await commit до contextApplied, звіряє authoritative receipt при lostACK, не повертає receipt map у браузер. Context adapter передає тільки proposalId/baseRevision/text, не caller path чи state.

UI показує «Додати до пам’яті», поточні факти можна розгорнути; нічого не пишеться до натискання «Запам’ятати». Старий replace-сценарій не змінений. Native kit може обрати append tool-description, не створюючи другого contextStore.
