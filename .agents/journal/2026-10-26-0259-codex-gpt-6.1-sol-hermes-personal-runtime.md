## Зроблено

Personal runtime з’єднує окремі AppStore/media/tools/читачі двох verifiedUID з одним Core/payer/outbox. Native контекст лишається єдиним. Registry відокремлює платника, Native home і явно заданий Firestore profileId. Немає Anthropic fallback чи ChatGPT login для дружини.

Оператор створює сховище окремо. Startup вимагає provision marker, повні критичні таблиці всіх DB, deletion anchor і приватні власні файли. Втрата/обрізання ledger або missing admission/draft/save table не створює порожню заміну. Cleanup пробує закрити всі handles і гарантовано затирає derived keys навіть при I/O fault.

/data-session приймає лише власний refreshToken під перевіреним bearer. Browser автоматично підключає свій Firebase session, коли новий runtime цього потребує. Повтор після data_auth_required відбувається лише після preflight відмови до admission. Паралельні підключення дедуплікуються, UID звіряється до/після fetch. Токен не зберігається у browser storage і не повертається з API. Сервер зберігає його шифровано; тільки trusted reader виконує власні Firebase правила.

HTTP transport тепер дозволяє обидва verified allowlisted UID через runtime.accepts, перевіряє авторизацію до body. Legacy single-owner сценарій збережений. Прогрів Native при ready connection не викликає модель, прибирає cold-start із5s браузерного вікна.
