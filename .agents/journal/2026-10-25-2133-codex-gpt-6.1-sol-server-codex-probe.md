## Ціль

За погодженням власника спочатку перевірити на сервері підпискове з’єднання Hermes із GPT-6.1 Sol, включно з поновленням авторизації. Перенесення справжнього персонального тренера та його приватної історії не входило у пробу.

## Що зроблено

- Прочитано встановлений Hermes і код за серверним pin. Підтверджено, що нинішній вебпрофіль окремий від наявного особистого тренера. Збережено продуктовий напрям: трекер харчування з окремими діями «Додати їжу» й «Тренер», месенджер, дата історії у хедері.
- Звірено хеші семи файлів серверного native клієнта. Підготовлено окрему одноразову пробу: новий device login власника, без копіювання активних refresh-токенів Mac; 2 CPU, 2 GiB, swap=0, core=0, окремий noswap tmpfs.
- Незалежний Codex-рев’юер перевірив транспортний лічильник, порядок refresh, одноразовий запуск та очищення. Виправлено armed cleanup і спостереження SSE при компресії. Його синтетичні перевірки не виконували зовнішніх запитів.
- Серверний dry-run штатного CodexAuxiliaryClient з MockTransport пройшов: два підставні POST, третій заблокований, зовнішніх модельних запитів нуль. Під час підготовки виправлено SFTP-режим створення файла й вибрано штатне середовище Python Hermes із залежностями.
- Власник виконав новий вхід OpenAI. Рівно два фактичні GPT-6.1 Sol POST успішні: 3,941 с та 2,440 с. Модель підтверджено terminal SSE обох відповідей. Native refresh повернув HTTP 200; токен поновився, записана пара використана наступним клієнтом без повторного входу.
- Тимчасові профіль, сховище, служба й файли проби прибрані. Адміністратора відкликано; відсутність у API та відхилений SSH підтверджені, три тимчасові Keychain-записи видалено. Чинний release незмінний, health200.
