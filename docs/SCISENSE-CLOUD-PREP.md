## Поточний результат

Після рішення Юрія реалізація локальна. API, G04 та synthetic budget/runtime підготовлені у codex/scisense-server-prep; Linux-збірка виконується в GitHub Actions. Mac потрібен для активного локального сеансу. Cloud task не створено.

CLOUD-PREP-01 ще не завершено: Linux Whisper на погоджених1CPU/2GiB не розпізнав жоден із6 UA/RU записів5/30/90s за45s. Результати у [звіті](evidence/linux-whisper-preparation-2026-10-21.json), CI39590783755. Після окремого погодження Юрієм проба на2CPU також завершилась6/6 таймаутами (CI39620593130);2GiB/45s/model збережені. Діагностика39622898172 підтвердила прочитання всього аудіо й використання майже2CPU протягом45s; це не зависання stdin. Пропозиція STT-SMALL-01 чекає рішення Юрія. Production лишається1CPU; модель/ресурси/таймаут автоматично не змінюються. Поточний [пакет підготовки](SCISENSE-SERVER-PREPARATION.md) перелічує перевірене та невиконані гейти.

## Що перевірено

- GitHub MILSPIL/nutrition-app публічний, не архівний. Гілка codex/voice-photo-entry опублікована, перевірений код: 3d897e13bb81ad6a1bf8f98aa3bffc78a2b918ca. Саме вона містить голос/фото та серверний план; починати лише з main або feat/voice-input неправильно. Нові зміни документації не змінюють цю кодову базу.
- PR8 відкритий як draft. Дві перевірки CI успішні на цьому SHA. [Запуск 39503591637](https://github.com/MILSPIL/nutrition-app/actions/runs/39503591637) реально виконав npm ci для застосунку й Worker, тести з demo Firebase та збірку на ubuntu-latest. Це доказ переносимості бази; серверний adapter, G04 і Whisper на Linux ще не перевірені.
- Обидва package-lock.json збережені в Git; усі записані resolved-залежності ведуть у registry.npmjs.org. Приватний npm-токен для них не потрібний.
- Codex CLI підтримує cloud list/exec. Читання списку задач завершилося успішно й повернуло 0 задач; це не доводить відсутності середовищ. Список проєктів desktop показує SciSense лише локально. Опубліковане середовище, GitHub OAuth у хмарі та cloud task ID ще не підтверджені.
- Особисті локальні skills і macOS MCP/Keychain не стають доступними у хмарі автоматично. Code Indexer тут індексує інші робочі дерева, тому для хмарної задачі джерелом правди будуть файли й точний SHA у Git.

## CLOUD-PREP-01: погоджена послідовність

1. **Місце виконання змінено Юрієм 2026-10-21: локальний сеанс**, від codex/voice-photo-entry (edf4ad8) у дочірній гілці codex/scisense-server-prep; Linux-перевірки у GitHub Actions. Хмарний запуск не відбувся: environment_repo_access_failed. Решта меж пакета збережена. Початковий варіант хмари лишається нижче як історія, не як наступна дія. **Початковий варіант: підготувати незалежне середовище.** Приватне середовище Codex Cloud тільки для MILSPIL/nutrition-app, без production-секретів і доступу до MS-WEB. Вибрати codex/voice-photo-entry, перевірити походження SHA; створити окрему дочірню гілку codex/scisense-cloud-server. Встановити залежності, виконати базові перевірки, опублікувати середовище й отримати ID хмарної задачі. Синхронізувати зміни через Git, не через локальні незакомічені файли. Зберегти в репозиторії вузькі правила для цієї задачі, бо особисті skills не синхронізуються. До фактичного запуску не повідомляти, що робота триває із закритим Mac.
2. **Виконати реалізацію за існуючим планом.** Серверний API із перевіркою JWT/Origin, скасуванням запитів і лімітами; G04 за канонічним підтвердженим запитом, атомарним прийняттям/відкликанням та A01–A09; Linux-пакет Whisper; синтетична репетиція одного бюджету й секрету. Після майбутнього розгортання старі зв’язки з тренером без доказу згоди потребуватимуть повторного підключення. У хмарній розробці справжні дані та правила Firebase не змінюються.
3. **Перевірити й підготувати результат.** Нові тести помилок, конкурентності, abort/restart/rollback; UI у власному headless-браузері GitHub Actions; Linux Whisper на синтетичних UA/RU записах; незалежне рев’ю ризикового коду. Відтворюваний PR із точними SHA, звітами та пакетом майбутнього встановлення на ntzg.pp.ua / MS-WEB. Пуші та створення PR дозволяються цим пакетом після його погодження; merge й автоматичний deploy не входять.
4. **Зупинитися перед production.** Передати один конкретний пакет команд, backup, TLS, доступів, перенесення одного бюджету й відкату. Адміністративний доступ, шляхи й остаточна продуктивність MS-WEB потребують окремої перевірки, а справжні ключі/привілейовані зміни/активація API потребують погодження цього конкретного пакета. Поточна оцінка цих дій не виконує.

## Залежності й межі перевірки

| Частина | Потрібно у хмарі | Як перевіряти |
| --- | --- | --- |
| Застосунок і серверні тести | Node 24.11.1, npm 11, обидва npm ci | test:voice-photo, test:phone-lab, build; нові тести adapter/budget після реалізації |
| G04 і сховище | Java 21, firebase-tools 15.2.1, Auth/Firestore emulators, demo-scisense | Лише синтетичні користувачі; жодної Firebase production-авторизації |
| Whisper | C/C++ compiler, CMake, Git; source d1be6fde11ac6e0407606b4e42fe72d34add8037; large-v3-turbo-q5_0 із SHA1 e050f7970618a659205450ad97eb95a18d69c9ee | Збірка для Linux CPU, 1 потік, 5/30/90 s; заміри RAM/часу, timeout/cleanup. Бінарник Mac не переноситься |
| Голос/фото UI | Зафіксовані Playwright/Chromium і переносимий ізольований runner у GitHub Actions | Наявні test:voice-photo-ui/test:phone-lab-ui містять абсолютний Mac launcher; адаптація входить до пакета. Вбудоване керування браузером Codex Cloud не обіцяється |
| Sonnet | Підставний HTTPS-провайдер і синтетичні відповіді/помилки | Модель лишається обраним Sonnet; жодних справжніх API-запитів або ключа Anthropic в середовищі підготовки |
| systemd/секрети | Шаблони units, тестовий секрет, перевірка можливостей VM | Не позначати cgroups/LoadCredentialEncrypted/привілейований install перевіреними, якщо VM їх не підтримує; фінальний доказ на цільовому сервері після погодження |

Мережа: лише потрібні GitHub/npm/Node/Java/емуляторні/Whisper-model джерела та їхні перевірені download-hosts. Окремо перевірити nodejs.org, storage.googleapis.com, huggingface.co та фактичні redirect-hosts; заборона на автоматичний перехід до необмеженого інтернету. Production API Anthropic/Firebase/xCloud/Cloudflare у середовищі підготовки не потрібні. Емулятори й сервер тесту слухають loopback; справжні записи їжі/медіа та сирі секрети не потрапляють у Git чи CI artifacts.

Перед великими завантаженнями перевірити вільний диск, RAM і CPU реальної cloud VM. Не замовляти більшу VM або платний runner автоматично. Benchmark хмари не доводить швидкість MS-WEB; звіт зберігає конфігурацію, а цільові 1 потік / 2 GiB / 45 s залишаються перевіркою кінцевого сервера. Публічні GitHub CI logs містять лише синтетичні дані.

- **Лише якщо з’явиться запит авторизації:** вхід у ChatGPT/GitHub, OAuth/2FA для доступу тільки до цього репозиторію. Готовність хмарного середовища й запуск перевіряє агент; відсутній transport для створення/публікації передається як точний UI-крок, а не замовчується. Документований шлях: Work in → Cloud → Select environment → Create environment; після перевірок Publish.
- **Перед реальним серверним запуском:** погодження вже готового production-пакета. Якщо використовуємо чинні ключ і budget marker із Keychain, Mac потрібен на один контрольований сеанс передавання й звірки, а не на всю розробку. Самостійне створення нового ключа не замінює звірку єдиного бюджету. Секрети не надсилати в чат.
- **Після розгортання:** перевірити на власному телефоні вхід, дозвіл мікрофона/камери, голос + фото → прев’ю → «Додати» → повторне відкриття. Це не може замінити емулятор.

Sonnet і колишня стеля $5 збережені як контекст. CLOUD-PREP-01 не активує ці $5, не переносить Keychain, не відкриває нового API-бюджету й не замовляє платних ресурсів. Хмарна робота користується доступними лімітами Codex; доступність і залишок перевіряються до запуску, перевищення/купівля не дозволені.
