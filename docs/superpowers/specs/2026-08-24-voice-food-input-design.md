# Спека: чесна «шкала здоров'я» + голосовий ввід їжі + автозвіт тренеру

Дата: 2026-08-24. Статус: затверджено Юрою (brainstorming-сесія Claude Code).
Мова спеки: українська.

## Навіщо (мета користувача)

Юра будує цю фічу насамперед для себе. Його слова: «я хочу навчитися
занотовувати все, що я їм... хочу, щоб мені було страшно, коли буде далеко
за сто відсотків». Він переїдає, бо не бачить, скільки з'їв у калоріях.
Рішення: (1) шкала, яка чесно показує переїдання і лякає кольором,
(2) ввід їжі голосом без тертя, (3) автоматичний звіт тренеру.

Довідка: програма тренера збережена в `knowledge/trainer-program.md`
(локально, НЕ комітити). Офіційна денна норма: 2305 ккал (Б 140 г,
Ж 70 г, В 235 г). Ваги продуктів у програмі СИРІ.

## Обсяг MVP: три етапи

Кожен етап самостійний і має цінність сам по собі. Порядок саме такий.

## Етап 1. Чесна «шкала здоров'я»

### Проблема в поточному коді

- `src/components/Header.js`: `ProgressRing` і `MacroProgressRow` обрізають
  прогрес на 100% (`Math.min(value / target, 1)`). Переїдання невидиме.
- `CALORIES_TARGET` обчислюється з макросів = 2130 ккал. Офіційна цифра
  тренера: 2305 ккал.
- `src/pages/ClientApp.js` (`addProduct`, `addProductWithCustomGrams`):
  для калорійної категорії «в» (ліміт 575 ккал) додавання понад ліміт
  БЛОКУЄТЬСЯ (toast + return). Користувач фізично не може записати правду.

### Зміни

1. `CALORIES_TARGET = 2305` (константа з коментарем «офіційна цифра
   тренера»; макроцілі 140/70/235 не міняються).
2. Кільце калорій і рядки макросів показують реальний відсоток без
   обрізання: 137% - це 137%. Поруч із значенням понад норму: «+N ккал
   понад норму» (для макросів: «+N г»).
3. Кольорова шкала стану (застосовується і до кільця, і до цифри):
   - до 85% норми: зелений (як зараз, #34C759);
   - 85-100%: жовтий/бурштиновий;
   - 100-120%: червоний;
   - понад 120%: темно-червоний + CSS-пульсація кільця.
   Пороги - константи в одному місці (Header.js або nutrition.js).
4. Візуально кільце заповнюється до 100% і далі НЕ крутить друге коло:
   повне кільце + колір стану + чесна цифра відсотка всередині.
5. Запис їжі більше ніколи не блокується. У `addProduct` і
   `addProductWithCustomGrams` блок «переліміт -> toast + return»
   замінюється на «додати + показати попередження» (той самий toast,
   але без return). `canAddCategoryProduct` лишається як розрахунок
   залишку, його результат використовується для попередження.

### Кого зачіпає

Зміна поведінки для ВСІХ користувачів додатка (клієнтів тренера теж).
Це усвідомлено: чесний лог кращий і для тренера, ніж заблокований запис.
Тести `nutrition.test.js` оновити відповідно.

## Етап 2. Голосовий ввід їжі

### Потік користувача

1. У `ClientApp` біля перемикача прийомів їжі кнопка з мікрофоном
   («Надиктувати»).
2. Відкривається `VoiceInputModal`: велике текстове поле. Юра тисне в
   поле, вмикає мікрофон КЛАВІАТУРИ телефона і диктує. Додаток зі звуком
   не працює взагалі - тільки з текстом (рішення: iOS Safari Web Speech
   API ненадійний, а клавіатурне диктування вже працює скрізь).
3. Кнопка «Розібрати» -> запит на Worker -> 2-4 секунди -> прев'ю:
   список рядків {продукт, категорія-літера, грами (сирі + готові, якщо
   відрізняються), ккал, позначка «оцінка AI» якщо є}. Грами можна
   поправити, рядок можна видалити.
4. Нерозібрані шматки тексту показуються окремим блоком «не розібрав: ...»
   (не вигадуються).
5. Кнопка «Додати в прийом» -> кожен рядок іде через наявний
   `addProductWithCustomGrams(letter, product, grams, userPortion)` у
   ПОТОЧНИЙ вибраний прийом (selectedMeal). Далі стандартний шлях:
   стейт -> автозбереження у Firestore -> тренер бачить як завжди.
6. Помилка мережі/Worker: повідомлення «Не вдалося розібрати, спробуй ще
   раз», текст у полі зберігається.

### Архітектура

```
Додаток (React) --POST /parse + Firebase ID token--> Cloudflare Worker
Worker: перевірка токена -> Claude API (ключ у секреті Worker) -> JSON
```

- Firebase-план у Юри безкоштовний (Spark), тому Cloud Functions
  недоступні. Worker - безкоштовний tier Cloudflare, вистачає з запасом.
- Ключ Anthropic живе ТІЛЬКИ в секреті Worker (`wrangler secret put
  ANTHROPIC_API_KEY`). У код і репозиторій не потрапляє.
- Worker перевіряє Firebase ID token (підпис через публічні ключі Google,
  aud = nutrition-tracker-ua). Без валідного токена: 401.
- CORS: тільки https://nutrition-tracker-ua.web.app і http://localhost:3000.

### Розбір AI

- Модель: `claude-opus-5` через офіційний SDK `@anthropic-ai/sdk` у Worker.
  Structured output зі строгою JSON-схемою. Орієнтовна вартість розбору:
  2-3 центи; при 3-4 на день - до ~3 доларів на місяць. Перехід на дешевшу
  модель - окреме рішення на етапі «відкрити всім».
- Системний промпт містить повний каталог продуктів з `PRODUCTS_DB`
  (літера, назва, стандартна порція raw, coef, БЖВ, ккал; ~60 позицій)
  і правила нижче. Каталог передається з додатка в запиті (single source
  of truth - products.js; Worker свою копію не тримає).
- Правила промпта:
  1. Кожен продукт мапиться на позицію каталогу, якщо є розумний збіг
     («варена картопля» -> «картопля», літера «а» або «г»).
  2. Сира чи готова вага: визначається зі слів («варений», «відварений»,
     «готовий» = готова; сухий/сирий продукт = сира; не зрозуміло -
     помітити state: "unknown", у прев'ю показати підказку). Перерахунок
     готова -> сира робить КОД додатка через coef з каталогу, не модель.
  3. Продукту нема в каталозі: модель сама оцінює БЖВ і ккал на 100 г,
     обирає найближчу літеру за профілем макросів, ставить
     `estimated: true`.
  4. «Смажив/смажена» без згадки олії: додати окремий рядок «олія ~10 г»
     з позначкою «додано автоматично, прибери якщо не треба».
  5. Побутові міри конвертувати: «ложка цукру» ~ 25 г (столова) / 8 г
     (чайна), «склянка молока» ~ 250 мл тощо; при сумніві - чайна чи
     столова - обирати меншу і позначати як оцінку.
  6. Обірвані/незрозумілі фрази (голосове розпізнавання глючить) - у
     масив `unparsed`, нічого не вигадувати.
- Формат відповіді Worker:

```json
{
  "items": [{
    "dictated": "варених картоплі 200 г",
    "matchedName": "картопля",
    "letter": "а",
    "gramsDictated": 200,
    "weightState": "cooked",
    "p": 2, "f": 0.4, "c": 16, "cal": 76,
    "estimated": false,
    "note": null
  }],
  "unparsed": ["і ще той самий..."]
}
```

  (`p/f/c/cal` - на 100 г. Сиру вагу модель НЕ рахує: перерахунок
  готова -> сира робить `toMealItems` через coef каталогу. Для продуктів
  з каталогу код бере БЖВ з каталогу за `matchedName`, а не з відповіді
  моделі; значення моделі використовуються тільки коли `estimated: true`,
  і тоді вони стосуються ваги в тому стані, як надиктовано, без
  перерахунку: gramsRaw = gramsDictated.)

### Нові артефакти коду

- `src/components/VoiceInputModal.js` - вікно вводу і прев'ю.
- `src/services/mealParser.js` - виклик Worker; чиста функція
  `toMealItems(parseResult, PRODUCTS_DB)`: валідація, перерахунок
  готове -> сире через coef, підстановка канонічних БЖВ з каталогу.
- `workers/meal-parser/` - код Worker (wrangler-проєкт: index.js,
  wrangler.toml, README з командами деплою).
- `ClientApp.js` - кнопка + передача пропсів (мінімальні зміни).
- Позначка `estimated: true` зберігається в елементі meals (нове
  необов'язкове поле; Firestore це переживає безболісно) і показується
  в списку прийому маленьким бейджем «≈ оцінка AI».

### Ліміт категорії «в» у прев'ю

Якщо розібране перевищує залишок 575 ккал категорії «в» - рядок у прев'ю
підсвічується попередженням («перевищить ліміт категорії на N ккал»),
але додавання дозволене (узгоджено з Етапом 1: не блокуємо, лякаємо).

Правка 2026-08-25 (виявлено при плануванні): звіт уже є в додатку.

## Тестування

- `nutrition.test.js`: оновити кейси блокування «в» (тепер: додає +
  повертає ознаку перевищення для попередження).
- Нові unit-тести (Jest, `react-scripts`):
  - пороги кольорів шкали (85/100/120) і текст «+N ккал»;
  - `toMealItems`: перерахунок cooked->raw через coef (рис 3.4, куряче
    філе 0.611, картопля 1), підстановка канонічних БЖВ, обробка
    `estimated` і `unparsed`;
  - `buildTrainerReport`: формат, пропуск порожніх прийомів.
- Worker: локальний тест `wrangler dev` + один інтеграційний прогін
  руками на реальних фразах Юри (його приклад зі сніданком - перший
  тест-кейс).
- Перед PR: `npm run test:ci` і `npm run build` (правило репозиторію).

## Безпека і секрети

- Ключ Anthropic: тільки Cloudflare secret. Локально зберігати за скілом
  secrets-keychain. Витік = ротація.
- Worker відповідає тільки залогіненим користувачам додатка (Firebase ID
  token) і тільки з дозволених origin.

## Процес

- Робота в НОВІЙ гілці від main (поточне робоче дерево містить чужі
  незакомічені зміни codex/stabilize-core-foundation - не чіпати).
- Спека - перший комміт нової гілки. Один етап = один PR (або менше).
- Деплой фронта: стандартний (`npx firebase-tools deploy --only hosting`).
  Деплой Worker: `wrangler deploy` (окремий крок, описати в README Worker).

## Не в MVP (свідомо)

- Запис/розпізнавання звуку в додатку (Web Speech API).
- Telegram-бот і будь-які автонадсилання звіту.
- Вибір прийому їжі голосом («сніданок», «обід»).
- Історія розпізнавань, доступ інших користувачів до голосового вводу
  (кнопку бачать усі, але це не рекламується; ліміти на Worker - питання
  етапу «відкрити всім»).
- Перехід на дешевшу модель, кешування промпта - оптимізації на потім.
