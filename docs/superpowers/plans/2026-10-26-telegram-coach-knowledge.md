## Блоки реалізації (повний перелік)

### 0. Закріпити джерело і дозвіл

Модель: поточний Codex; ризик: приватні дані й неповний експорт.

- Отримати явне погодження цього локального плану, включно з двома окремими приватними індексами через CLI і task-only data_dir (без реєстрації у загальному MCP-сервері). Це вузький виняток до старого правила Goal про неіндексування, а не дозвіл класти дані в індекс коду.
- Попросити завершений повторний експорт цього самого чату у нову папку, зі всіма потрібними видами медіа й максимальним доступним лімітом розміру. HTML підтриманий, вимоги перейти на JSON немає. Пропущені стікери також відновити або отримати явний виняток; за власним рішенням їх не викреслювати.
- Звірити corpus_id/message_id, payload revisions та перетин діапазонів обох експортів, зберегти версії й приватний manifest. Поза перетином позначати outside_coverage, не видалення. Якщо користувач ще готує медіа, дозволені подальші блоки тільки для наявної частини з позначкою incomplete; повноту не оголошувати.
- Перевірити git/worktree й вибрати окрему task-гілку без чужих незавершених змін. Приватний runtime і експорт ніколи не комітити. git add тільки з явними перевіреними шляхами цього інструмента, нейтральних docs/ і власного журналу; git add -A/крапка заборонені. Наявні чужі untracked knowledge/profile/training/zip не включати. Код інструментів, синтетичні фікстури та знеособлені документи комітити окремими блоками й push без force.

### 1. Облік і незалежні перевірки

Модель: поточний Codex; ризик: непомітна втрата авторства, ID або вкладень.

- Спершу написати `tools/telegram-coach/verify.py` і синтетичні негативні фікстури C01–C08: joined/forward/reply, повторне медіа, заглушка без href, кілька HTML-сторінок, змінений файл, вихід шляху за source root, неправдивий факт без джерела. Показати очікувані FAIL; це не тести реалізації, що повторюють її результат.
- Тоді зробити мінімальний конвеєр нормалізації й обліку в тому самому `tools/telegram-coach/`. Обмежений HTML-адаптер ledger: BeautifulSoup із зафіксованою версією, тільки структура Telegram і джерельні поля. Не змінювати Code Indexer і не робити власний семантичний індекс. Незалежний verifier читає HTML через стандартний html.parser і власні еталонні фікстури; не імпортує адаптер і не бере його counters. SHA та source_version незалежні від пагінації.
- Облік усіх source slots окремо від унікальних файлів. Номер у назві файла не вважати кількістю повідомлень. Звірити незалежний HTML-підрахунок і реєстр, перечитати hashes.
- Приватні outputs: source-manifest/messages/media/links. C01/C02/C06 мають свіжі докази; у Git лише інструмент, фікстури й загальна нотатка.

### 2. Проба й пакетна обробка медіа

Модель: поточний Codex для QA, локальна Whisper для STT; ризик: неточні числа/вправи, довгий прогін, незавершені файли.

- Окремий venv; перед встановленням звірити офіційний код, зафіксувати версію та lock. Вже наявні small/large-v3 caches перевірити на цілісність; пакет у базовому Python відсутній. Нічого не встановлювати в runtime чинного Hermes.
- Проба до batch: зафіксувати 8 уривків сумарно 6–10 хв за матрицею специфікації, обидва автори й три періоди; щонайменше один приклад відео. Еталони й записи слухової перевірки потрібні для порога 8/8 основних повідомлень, нуля непокритого мовлення та нуля непозначених суттєвих помилок після звірки. Зберегти незалежну ручну/слухову звірку там, де інструменти дозволяють її зробити; неможливість послухати не підміняти словом verified. Виміряти час/RAM, повноту сегментів, конкретні помилки; невизначене позначити для уточнення.
- Основний кандидат: локальний large-v3, CPU int8, одна модель/черга, спочатку cpu_threads=4. Small придатний лише для порівняння швидкості/пошуку, поки проба не доведе потрібної якості. Параметри проби записати явно: task=transcribe, language=None, multilingual=True для змішаних записів, word_timestamps=True, vad_filter=True з консервативною межею тиші 2000мс; порівняти з vad_filter=False на пробі. Початкові no_speech_threshold=0.6, log_prob_threshold=-1.0, compression_ratio_threshold=2.4 є сигналами до перевірки, не доказом правди. Зберігати метрики/налаштування й мовні перемикання; вихід за пороги або розбіжність дає review_required. Після проби повідомити оцінку тривалості; не запускати невідомо довгий batch без явної межі й відновлення.
- Перед STT увімкнути HF_HUB_OFFLINE/local_files_only і пер-процесну заборону мережі (macOS Seatbelt/sandbox-exec, якщо підтримано); контрольний локальний TCP-сервер має бути доступний без guard і недоступний під ним. Якщо цей guard не перевірено, приватний STT не запускати. Транскрипція всіх доступних унікальних аудіодоріжок з таймкодами та provenance, без перекладу. Генератор сегментів має бути повністю вичерпаний до позначки success. Одна помилка не обриває пакет; один контрольований повтор, далі error і продовження. Ключ кешу включає SHA, модель і налаштування; atomic output, контроль одного writer, durable checkpoint.
- Повністю декодувати відео, окремо облікувати декодовані/відібрані/переглянуті інтервали; огляд кадрів ≤1с, сцени й уточнення ≥4кадри/с у складних місцях. sampled не видавати за безперервний перегляд. Переглянути кожне фото; документи, GIF, стікери, звичайне аудіо і дзвінки провести через повну матрицю типів специфікації. Перегляд стікерів не має вищого пріоритету за тренувальне медіа, але їхній стан обліковується.
- Після інвентаризації оцінити також кількість кадрів/сторінок і час візуальної перевірки. Contact sheets та квитанції перегляду зберігати одразу; checkpoint містить наступний file/interval, щоб продовжувати між сесіями без удаваного перегляду. Довести interruption/resume, corrupt input і single-writer на копіях. Приватні transcripts/visuals/reviews; C03/C07.

### Уточнення виконання, 2026-10-27

Після проби власник явно відповів: «Так, продовжуй чернеткову розшифровку». Це дозволяє локальну обробку решти аудіо без удаваного проходження слухового гейта. Усі результати залишаються `asr_unverified`; програма й кандидат Hermes використовують лише окремо підтверджені факти. Пакет із такими прогалинами має статус `partial`.

Для повного пакета обрано локальний `mlx-whisper` 0.4.3 / MLX 0.32.4 із large-v3 та `no-vad`. На тій самій обмеженій пробі час роботи становив близько 131 с проти 753 с CPU без VAD і 834 с CPU з VAD. Це порівняння швидкості, не доказ точності. Модель завантажена локально; мережевий guard, атомарні результати, контроль кешу й граничний час збережені. Один запуск має м’яку межу 1700 с та жорстку 1800 с; наступний продовжує готовий кеш.

### 3. Пошук і синтез

Модель: поточний Codex; ризик: змішати історичний факт, чужу цитату та поточну рекомендацію.

- Перевірити CLI task config: data_dir=.agents/runtime/telegram-coach-2026-10-26/indexer-store, локальний embedding, жодного remote endpoint/server/MCP. Заморожений HTML індексувати parser=telegram, Markdown/транскрипти окремо parser=documentation. Watch=false. Індекси й службові логи приватні в task runtime; глобальний сервер не реєструє ці джерела. Не експортувати їх у `.codeindexer/` проєкту.
- Прочитати весь текст і результати медіа, вести покриття кожного повідомлення/вкладення та зворотне зіставлення кожної рекомендації/зміни/самоспостереження з facts.jsonl і каталогом. Стани та owner waivers тільки за визначенням специфікації; unreadable не дорівнює irrelevant. Сформувати шість knowledge-документів і training-program-draft із джерелами. Включити зміни, заміни, прогресію, зворотний зв'язок і питання; не робити актуальну програму шляхом механічного вибору останньої дати.
- Усі твердження програми/майбутнього Hermes звірити з першоджерелами й класифікувати text/visual/audio_verified, asr_consistent або owner_confirmed; лише збіг двох ASR не дає audio_verified. Немає підтвердженого каналу прослуховування: суттєві аудіофакти звірити з прямим текстом або дати власнику таймкоди для підтвердження; сумнівне лишити питанням. Незалежний Codex цієї задачі заздалегідь фіксує 12 retrieval cases з source IDs (3 текстові/3 голосові/2 візуальні та 4 негативні, мінімум 3 періоди). Потім один semantic-запит на індекс, top-5 на кожен; оцінка C04/C05 не приймає повернення всього корпусу. Відсутнє відео не реконструюється з назви вправи.
- Повторний експорт додає/виправляє лише відповідні матеріали, але транзитивно позначає застарілими залежні транскрипти/факти/каталог/програму/кандидат Hermes/індекси/оцінки через derived_from ID+SHA; незалежні результати зберігаються; після оновлення повторити потрібні перевірки.

## Межі та відкат (повний перелік)

- До першого output зберегти source SHA; originals не писати. Синтетичні пошкодження лише на копіях.
- За crash продовжити з останніх цілісних outputs, не видаляти джерела. Потрібні зміни версії створюють нову ревізію, а не переписують докази старої.
- Rollback локального конвеєра: `git revert` конкретного блоку; приватні дані залишаються для повторної перевірки. Видалення приватних матеріалів лише за окремим запитом.
- Жодних production, scheduler, Keychain, листування з тренером, витрат або зміни моделей Hermes у цьому плані. Локальне встановлення потрібних відкритих пакетів без оплати дозволяється погодженням плану.
- Майбутнє live-погодження включатиме fresh revision, backup/restore, перевірку того самого профілю й контрольних відповідей; жодної сліпої заміни native history або memory-файлів.
