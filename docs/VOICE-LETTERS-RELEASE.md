## Склад пакета

Збірка UI 1.8.0 із `/meal-api` та вимкненими lab-режимами; Node API `server/`, Worker source, незмінна proposal, допоміжні runtime-модулі й pinned dependency `jose`. Manifest містить SHA джерела та SHA256 файлів. Конфіг `deployment.json` у пакеті є неактивним шаблоном, його не можна копіювати поверх чинного manifest без узгодження з activation receipt. Ключів, приватних записів і бюджету в пакеті немає. Node 24.22.1, чинні 1 CPU / 2 GiB; розширення ресурсів не потрібне.

## Наступний етап 7, тільки після окремого дозволу

1. Прочитати актуальний SHA сервера, manifest, квитанцію активації та стан того самого ledger; звірити чинні моделі й доступний залишок cap. Перевірити старий UI і резервну копію лише потрібних файлів. Старий тимчасовий admin не відновлювати автоматично.
2. Підготувати новий release directory з API v2. Зберегти наявні зашифровані credentials, UID allowlist, ledger і cap5000000; додати кандидат до дозволених releases у чинній квитанції, звірити configHash. Не запускати transfer/init, не скидати reservations, не змінювати rules/IAM. API v1 залишається сумісним із чинним UI.
3. Після перевірки manifest/receipt встановити лише API v2. Виконати рівно шість дозволених аналізів L10 без автоматичних повторів: 12 позитивних продуктів двома групами, 4 негативних, 2 етикетки, один запис на 20 продуктів. [Заморожені входи](../scripts/fixtures/voice-letters-l10/cases.json). Sonnet `claude-sonnet-5-5`, голосовий провайдер Groq Free `whisper-large-v3` незмінні. Входи синтетичні; результати не записувати в production-щоденник.
4. Звірити фактичний `analysisMeta` з envelope, 12 правильних відповідників і станів, невизначені норми, збереження ручної літери/кількості після фото. Для 20 рядків: `end_turn`, рівно20 валідних рядків, `outputTokens<=3686`, request limit4096. За FAIL зупинитися, не послаблювати expected і не збільшувати output/cap. Справжня точність зараз невідома.
5. Лише за PASS L10 опублікувати UI цього самого кандидата. Звірити SHA й asset-хеші, повторний вхід, ready без мікрофона, явний старт, один запис, перечитування та відсутність дубля. Юрій перевіряє фізичний телефон; ця частина L08 залишається pending до його проби.

Максимальна сума резерву шести запитів буде розрахована за замороженим каталогом/схемою й фактичним чинним залишком того самого $5 перед дозволеним запуском. У локальному етапі баланс не читається, гроші не витрачаються. Поточні unit-тести доводять облік доданого UTF-8 prompt/schema у резерві, але не фактичний рахунок провайдера.

## Відкат

До клієнтської публікації: повернути попередній API release і відповідний manifest; зберегти всі нові резерви та витрати. Після публікації: UI/API повертаються разом до перевіреного попереднього release; дані, credentials, ledger, receipt history й writer fence не відкочуються. Сумісність старого `commitMealDay` для quantity і нових allocation перевірена локально. Якщо свіжий стан не відповідає перевіреному сценарію, зупинити нове додавання до сумісного виправлення, не накривати щоденник старою копією.
