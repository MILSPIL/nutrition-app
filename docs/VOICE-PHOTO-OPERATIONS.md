# Голос і фото: перевірка та межі запуску

Погоджений сценарій і критерії: [специфікація](superpowers/specs/2026-10-20-voice-photo.md), [план](superpowers/plans/2026-10-20-voice-photo.md), [Goal](PRODUCT-GOAL.md).

## Сховище

`users/{uid}/mealHistory/{YYYY-MM-DD}` є джерелом дня. Транзакція читає owner/day і записує їжу, revision, submissionMarkers та сумісну проєкцію users разом. Налаштування користувача оновлюють тільки передані поля. Нові items зберігають quantity, nutritionBasis, nutrients на основу, source та itemId; читачі використовують ту саму математику. Калорії етикетки не перераховуються через 4/9/4.

Старі недатовані meals не мігрують автоматично. Користувач обирає дату; тотожний день не дублюється, різні списки об’єднуються тільки явною дією. Відкритий порожній день не заповнюється попереднім root snapshot.

## Лабораторія

Повний локальний UI QA: `scripts/voice-photo-ui.mjs` через зареєстрований `agent-test-browser`. Він примусово задає `REACT_APP_LOCAL_LAB=1`, `REACT_APP_PILOT_MODE=1`, endpoint `http://127.0.0.1:8787` і збирає в ignored `tmp/voice-photo-build`. Firebase тільки `demo-scisense`, Auth 9099/Firestore 8088 на loopback; браузерний сервер 4178. Worker-відповіді підставні через browser routing. Реальні MediaRecorder, WAV, нормалізація зображень, IndexedDB і Firestore commit перевіряються локально.

На іншому hostname LAB завершується до ініціалізації Firebase. Для реального телефона спочатку потрібен окремий HTTPS reverse proxy до емуляторів та wrangler dev, demo-конфіг без production fallback і явна довіра власника до сертифіката. Також потрібен окремий test-only адаптер Auth emulator, бо production Worker приймає лише RS256 JWT й відхиляє непідписані emulator-токени. Цей канал ще не налаштований, власник не встановлював довіру. Desktop QA не закриває телефонні критерії.

`REACT_APP_MEAL_API_URL` у звичайній збірці порожній за замовчуванням. Мікрофон доступний, але мережеве розпізнавання пояснює, що сервіс ще не підключено. Увімкнення endpoint не обходить серверну автентифікацію або погодження бюджету.

## Пілот і приватність

Облік працює лише при `REACT_APP_PILOT_MODE=1`. IndexedDB зберігає псевдонімні IDs, часи, дії/виправлення/уточнення, факт фото й результат; без їжі, тексту, БЖВ, медіа, UID або email. Кожен новий запис або явний повтор невдалої API-обробки має окрему спробу. Відмови й закриття лишаються у знаменнику; повтор читання невизначеного commit не додає спроби. Успіх потребує підтвердження правильності учасником; частковий запис або ручні БЖВ не зараховуються.

Панель пілоту дозволяє локально експортувати вимірювання й видалити їх. Після reload незавершена спроба стає abandoned; unknown перевіряється за marker, але правильність не підтверджується автоматично. Недоступність локального сховища позначає весь пілот непридатним до оцінки. Дані старші 30 днів видаляються при наступному відкритті.

Аудіо/фото/розшифровка живуть тільки у пам’яті відкритої чернетки, очищаються при закритті, виході й успішному збереженні. Після невизначеного збереження окрема команда з нормалізованими позиціями без сирих медіа лишається в пам’яті відкритої сторінки для тотожного повтору; очищення описане нижче. Це не означає нульове зберігання у зовнішніх провайдерів: їхню політику треба погодити перед реальним API.

Конкретний пакет наступного API-прогону: [моделі, кредити, стеля витрат і тестові матеріали](VOICE-PHOTO-LIVE-APPROVAL.md). Він має статус pending і не вмикає live.

## Релізні гейти

1. Незалежне рев’ю й зелений CI для одного SHA; V01–V03 на fixtures є частковими доказами.
2. Окремо погодити проєктні API-акаунти, точні моделі/тарифи, абсолютний бюджет, синтетичні матеріали та політику передачі; зараз ключі SciSense у Keychain не знайдені, чужі не використовуються.
3. Реальний телефон/API V09. Встановлення довіри до локального сертифіката виконує власник.
4. G04 доступ клієнт/тренер до будь-якого приватного пілоту. Реалізація access-плану не входить у цей дозвіл.
5. G08 має довести сумісність старих відкритих клієнтів: старі writers повинні бути заблоковані або контрольовано оновлені до зміни сховища. Наявний writerVersion=2 сам цього не забезпечує.
6. Окреме рішення про production; локальний PR не є публікацією. Після G04/release: 7 днів, ≥10 голосових спроб, ≥5 із фото, ≥80% усіх спроб правильні й повні без ручного пошуку/введення БЖВ. Продукт приймає Юрій.

Після невизначеного commit дозволено явно закрити модалку. Та сама команда лишається у пам’яті відкритої сторінки; головна кнопка «Повторити» перевіряє/повторює її з тим самим submissionId. Нове додавання заблоковане до визначеного результату. Успішний повтор оновлює облік пілоту, але правильність їжі підтверджує учасник.
