# Телефонна лабораторія SciSense

Стан 2026-10-20: цільовий запуск Юрія перенесено на `https://ntzg.pp.ua` на MS-WEB Server. Цей документ описує допоміжну локальну лабораторію. Whisper + Sonnet і $5 погоджено; адаптери реалізовано, реальні Sonnet-виклики й live binding ще не активовано. Реальний Whisper на Mac розпізнав синтетичну українську фразу за 2872 мс. Це не доказ роботи сервера або фізичного телефона.

## Підготовка й запуск на Mac

Node з `.nvmrc`, встановлений Firebase CLI та Python keyring. Команди виконуються з кореня цього робочого дерева:

```sh
npm run lab:phone:prepare
npm run lab:phone
```

`prepare` вибирає єдину приватну IPv4 на en0, або приймає явний IP після `--`. Генерує короткостроковий CA на 3 дні й серверний сертифікат на 2 дні, збирає окремий frontend у `tmp/phone-lab/build`. Жодного встановлення кореневого сертифіката в системі автоматично. Приватні ключі генеруються через pipe; CA private key не зберігається, server key лежить у macOS Keychain `scisense-phone-lab` / `tls-key`. У теці є тільки публічні `.crt`, несекретна конфігурація та збірка. Повторний `prepare` створює новий CA; телефон потребуватиме нової явної довіри. Не виконувати його під час активного тесту.

`start` запускає тільки demo-scisense Auth/Firestore на loopback і один HTTPS-вхід на конкретній адресі Mac, порт 8443. У виводі буде фактична повна адреса. Термінал має лишатися відкритим. Ctrl+C завершує власні сервери. Після зупинки емуляторів синтетична база видаляється; оновлення сторінки під час активного запуску зберігає день. Це не довгостроковий щоденник.

## Один раз на телефоні для цього CA

1. Mac і телефон мають бути в одній Wi-Fi мережі. Передайте лише публічний `tmp/phone-lab/ca.crt` на телефон, наприклад через AirDrop.
2. Власник встановлює профіль сертифіката. На iPhone це «Параметри → Загальні → VPN і керування пристроєм», потім «Загальні → Про пристрій → Довіра сертифікатам» і повна довіра до `SciSense temporary phone lab`. Цю дію робить Юрій; тест браузера її не заміняє. На Android установіть цей CA у налаштуваннях сертифікатів користувача й перевірте підтримку браузером.
3. На Mac відкрийте адресу з рядка `setup`. Код видно тільки при з’єднанні із самого Mac. На телефоні відкрийте основну адресу й введіть код. Він діє 15 хвилин та один раз; сеанс телефона діє 4 години. Код і cookie не друкуються в логах або URL.
4. Натисніть «Увійти в тестовий простір». Це один синтетичний користувач. Далі мікрофон на головній сторінці. До явного enable-live розпізнавання повідомляє, що сервіс ще не підключений; підставного успішного розпізнавання в цьому CLI немає.
5. Після завершення тесту видаліть профіль тимчасового CA з телефона. Новий код сполучення потребує перезапуску лабораторії, не нового сертифіката.

## Межі та перевірки

- Production handler з RS256 незмінний. Test-only gateway приймає demo JWT лише з дійсним сполученням, дозволеним UID, issuer/audience/часом і підтвердженням користувача емулятором.
- Host/Origin, усі носії Authorization, project і WebChannel session перевіряються. Upstream заданий тільки як loopback, це не довільний HTTP-проксі.
- Frontend має явний build-time HTTPS origin; неправильний origin або phone mode без local lab зупиняє запуск. Для Firestore використано `initializeFirestore` з локальним host та `ssl:true`, без зміни production-конфігурації.
- `prepare` лишає live=false. Окрема команда `node scripts/phone-lab.mjs enable-live` перевіряє погоджену пропозицію, hash моделі та Keychain і створює бюджет один раз. Її в цій сесії не запускали: прогін переноситься на сервер. OpenAI не використовується. `start` із live=true читає тільки окремий Anthropic-ключ у пам’ять.
- `scripts/phone-lab/sqlite.mjs` підготовлений для того самого PilotBudget, протестований на перезапуску, іншому UID, порожньому/відсутньому файлі та зміні стелі. Live binding ще не активований. Створити новий фінансовий бюджет замість пошкодженого без звірки витрат заборонено.
- Маркер прогону у Keychain не дозволяє створити нові $5 після втрати SQLite. Whisper отримує WAV через stdin, повертає текст у stdout, має timeout/abort, одну одночасну транскрипцію й перевірку тиші.
- Сертифікати, pairing, бюджет і медіа не потрапляють у Git. Сирі медіа обробляються в пам’яті. API-ключі після погодження тільки Keychain → пам’ять процесу.

```sh
npm run test:phone-lab
npm run test:phone-lab-ui
```

Другу команду виконує лише зареєстрований `agent-test-browser run scisense-phone-lab` поза sandbox. QA використовує окремий Chrome, реальні emulator/WAV/SQLite, але відповіді моделей підставні; перевірка довіри браузера до тестового TLS обходиться тільки в цьому ізольованому QA. Node HTTPS перевіряє сертифікат через конкретний CA без обходу TLS. Власні browser/context/server закриваються у finally; квитанція launcher є частиною доказів.

Первинні джерела: [Firebase settings host/ssl](https://firebase.google.com/docs/reference/js/firestore.firestoresettings), [Auth emulator та непідписані токени](https://firebase.google.com/docs/emulator-suite/connect_auth), [Node HTTPS](https://nodejs.org/api/https.html), [Node SQLite](https://nodejs.org/api/sqlite.html), [ручна довіра сертифіката на iPhone](https://support.apple.com/en-gb/102390). Context7 мав вичерпану квоту; додатково прочитано встановлений Firebase SDK для точних WebChannel/REST маршрутів.
