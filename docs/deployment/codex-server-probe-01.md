# CODEX-SERVER-PROBE-01: перевірка підпискового Hermes на сервері

Дата: 2026-10-25. Власник погодив окрему практичну пробу в голосовій розмові. Перенесення персонального тренера ще не виконується.

## Що перевіряємо

Чи може наявний серверний Hermes отримати відповідь **GPT-6.1 Sol** через новий вхід OpenAI, а потім продовжити роботу після штатного поновлення авторизації. Успіх цієї проби дасть підставу планувати незалежного від Mac тренера.

| Варіант | За | Проти |
|---|---|---|
| Hermes на сервері через OpenAI Pro | Сайт працює за вимкненого Mac; та сама модель і спосіб входу | Потрібен окремий серверний вхід; доступ моделі й поновлення перевіряються практично; витрачається квота підписки |
| Hermes на Mac із захищеним підключенням сайта | Менше перенесення наявного тренера | Сайтова консультація залежить від живлення, мережі й доступності Mac |
| Чинний вебтренер через Anthropic API | Уже працює на сервері | Окрема API-оплата та інший персональний профіль |

Рекомендація: спочатку перевірити серверний варіант через Pro. Він відповідає бажанню вимикати Mac і користуватися наявною моделлю. Залишення на Mac буде запасним варіантом, якщо практична проба виявить обмеження.

## Порядок проби

1. Звірити хеші наявного Hermes з перевіреною версією. Не оновлювати робочий runtime.
2. Створити окреме тимчасове середовище: 2 CPU, 2 GiB RAM, swap вимкнений для процесу, core dumps вимкнені. Файли авторизації лише у тимчасовому `noswap` tmpfs із правами 0700/0600.
3. Перевірити клієнт Hermes на синтетичній відповіді без зовнішньої моделі, включно із забороною третього запиту.
4. Власник виконує новий вхід OpenAI через офіційну сторінку device login. Активні токени Mac не копіюються. Код входу одноразовий і має обмежений строк.
5. Один короткий запит GPT-6.1 Sol через штатний `CodexAuxiliaryClient` Hermes. Перевіряються HTTP-успіх, очікувана відповідь та модель із фактичного SSE, а не лише модель запиту.
6. Штатне поновлення нової авторизації Hermes, перевірка записаної пари токенів без виведення значень, другий короткий запит.
7. Видалити тимчасовий профіль, розмонтувати сховище, відкликати тимчасовий адміністративний доступ, перевірити відмову SSH та видалення тимчасових Keychain-записів. Перевірити health чинного застосунку.

Сумарна межа: **два фізичні inference POST**, без автоматичних повторів чи платного fallback. Одна проба має стійкий маркер, який забороняє повторний запуск із невизначеним результатом. Таймаут модельної фази 45 секунд; очікування входу окреме, до 15 хвилин.

## Коли проба пройдена

- Використовується серверний клієнт Hermes на Linux, без залежності від Mac.
- Новий вхід використовує `openai-codex` та `auth_mode=chatgpt`.
- Обидві відповіді успішні, фактична модель відповідає GPT-6.1 Sol.
- Другий запит працює після успішного штатного поновлення авторизації.
- Підтверджені межа викликів, очищення й незмінний робочий сайт.

Це перевірка підпискового з’єднання клієнта Hermes. Вона ще не доводить роботу повного тренера, тривалу стабільність, перенесення історії або розділення двох користувачів.

## Наступний етап після успіху

Підготувати специфікацію перенесення справжнього тренера: один канонічний сервер, підключення Hermes Desktop, безпечне збереження авторизації, резервне копіювання й окремі профілі/пам’ять/історія за підтвердженим акаунтом. Для дружини потрібні власні цілі й контекст. Її дані та умови використання підписки не є предметом цієї проби.

Окремо зберігається погоджений продуктовий напрям: верхня «Додати їжу» для обліку харчування; плаваюча «Тренер» для консультацій; повідомлення як у месенджері; дата історії в хедері; перед записом їжі коротке прев’ю й одна «Додати».

## Фактичний результат

Проба 2026-10-25 пройдена: два фактичні GPT-6.1 Sol запити через ChatGPT/Codex, 3,941 с та 2,440 с. Модель підтверджена у terminal SSE обох відповідей. Штатний refresh повернув HTTP 200, оновлена пара записана й використана другим клієнтом без повторного входу.

Профіль, tmpfs, transient unit і тимчасовий адміністратор прибрані; SSH відхилено, три тимчасові Keychain-записи видалено. Робочий release незмінний, health 200. [Санітизований доказ](../evidence/codex-server-probe-2026-10-25.json).

Висновок: підписковий клієнт Hermes працює на сервері. Перенесення справжнього тренера та інтеграція двох акаунтів ще потребують наступного плану. Конкретний тариф ця серверна проба не визначає; акаунт для входу вибрав власник.
